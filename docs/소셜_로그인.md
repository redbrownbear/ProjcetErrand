# 카카오 · 네이버 로그인

로그인 화면 맨 위에 **카카오로 시작하기 · 네이버로 시작하기**. 이메일 로그인 · 가입은 아래 '테스트 계정(이메일)'으로 그대로 남겨 둔다.

## 흐름

1. 앱이 각 회사 SDK로 로그인 → 액세스 토큰 (`lib/features/auth/services/social_login.dart`)
   - 카카오: 카카오톡이 깔려 있으면 카카오톡으로, 아니면(또는 실패하면) 카카오계정 웹 로그인
   - 네이버: 네이버 앱 · 웹 로그인(`flutter_naver_login`)
2. 서버 함수 `socialSignIn`(`functions/src/auth/`)이 그 회사 API로 토큰을 확인
   - 카카오: `/v1/user/access_token_info`의 `app_id`가 우리 앱(`KAKAO_APP_ID`)인지 → `/v2/user/me`
   - 네이버: `/v1/nid/me` (`resultcode` `00`)
3. 서버가 Firebase 계정(uid `kakao:{회원번호}` · `naver:{고유 식별자}`)을 처음이면 만들고(이름 = 닉네임, 없으면 '카카오 이웃' · '네이버 이웃')
   커스텀 토큰을 돌려줌 → 앱 `signInWithCustomToken`
4. 그 뒤는 이메일 계정과 같다. 필수 약관 동의가 없는 계정이라 로그인 직후 **동의 화면**(`ConsentGateScreen`)이 뜬다
5. 로그아웃하면 SDK 쪽 로그인도 끊는다(다음 사람이 다른 계정을 고를 수 있게)

- 이메일은 받지도 저장하지도 않는다(같은 이메일의 이메일 계정과 부딪히고, 로그인에 필요 없음). 동의항목은 **닉네임만**.
- 같은 사람이라도 이메일 · 카카오 · 네이버 계정은 서로 다른 계정이다(계정 연결은 아직 없음).
- 키가 없으면(secrets.json에 안 넣었거나 웹 · 데스크톱) 버튼이 안 보이고 이메일 로그인만 보인다.

## 설정 (사람이 할 일)

### 1. 카카오 디벨로퍼스 (developers.kakao.com)

1. 내 애플리케이션 › 애플리케이션 추가 (앱 이름 겸사겸사)
2. **앱 키**: 네이티브 앱 키 → `secrets.json`의 `KAKAO_NATIVE_KEY`. **앱 ID**(숫자) → 서버 `KAKAO_APP_ID`(아래 4)
3. 플랫폼 › Android 등록 — 패키지명 `com.gyeomsagyeomsa.app`, **키 해시**
   - 디버그: `keytool -exportcert -alias androiddebugkey -keystore %USERPROFILE%\.android\debug.keystore -storepass android -keypass android | openssl sha1 -binary | openssl base64`
   - 출시: 업로드 키 + 플레이 콘솔 › 앱 무결성의 **앱 서명 키** SHA-1을 base64로 바꾼 값도 추가(플레이가 다시 서명하므로)
4. 카카오 로그인 › 활성화 ON
5. 동의항목 › **닉네임** 필수(또는 선택). 다른 항목은 켜지 않는다

### 2. 네이버 개발자센터 (developers.naver.com)

1. Application › 애플리케이션 등록 — 사용 API **네이버 로그인**, 제공 정보 **별명**(필수)
2. 로그인 오픈 API 서비스 환경 › Android — 다운로드 URL(스토어 링크, 출시 전엔 임시 주소), 패키지명 `com.gyeomsagyeomsa.app`
3. Client ID → `NAVER_LOGIN_ID`, Client Secret → `NAVER_LOGIN_SECRET` (검색 API용 `NAVER_SEARCH_*`와 같은 애플리케이션이어도 되고 달라도 된다)
4. 처음엔 '개발 중' 상태라 **멤버 관리에 등록한 네이버 아이디만** 로그인된다. 출시 전에 **검수 요청**

### 3. 앱 키 (secrets.json, 저장소 밖)

```json
"KAKAO_NATIVE_KEY": "…",
"NAVER_LOGIN_ID": "…",
"NAVER_LOGIN_SECRET": "…"
```

`flutter run --dart-define-from-file=secrets.json` — 안드로이드 매니페스트(카카오 돌아오는 주소 `kakao{키}://oauth`, 네이버 meta-data)도
`android/app/build.gradle.kts`가 같은 값을 읽어 채운다. Android Studio 실행 설정의 Additional run args에도 같은 옵션을 넣어야 버튼이 보인다.

### 4. 서버

1. `functions/.env.projecterrand`에 `KAKAO_APP_ID=숫자` (비밀값 아님 — 커밋해도 됨). 비어 있으면 카카오 로그인을 서버가 거부한다
2. Google Cloud 콘솔 › IAM — Cloud Functions가 쓰는 서비스 계정(`{프로젝트 번호}-compute@developer.gserviceaccount.com`)에
   **서비스 계정 토큰 생성자**(Service Account Token Creator) 역할 추가, API 라이브러리에서 **IAM Service Account Credentials API** 사용.
   안 하면 커스텀 토큰을 못 만들어 로그인이 '처리하지 못했어요'로 끝난다
3. `firebase deploy --project dev --only functions` (새 함수 `socialSignIn`)

### 5. iOS (나중 — 번들 ID를 정한 뒤)

- 카카오: Info.plist `LSApplicationQueriesSchemes`(`kakaokompassauth`, `kakaolink`, `kakaoplus`), URL Types에 `kakao{네이티브 앱 키}`, 카카오 디벨로퍼스 플랫폼 iOS에 번들 ID
- 네이버: Info.plist `NidClientID` · `NidClientSecret` · `NidAppName` · `NidUrlScheme`, `LSApplicationQueriesSchemes`(`naversearchapp`, `naversearchthirdlogin`),
  URL Types, `AppDelegate`에서 `NidOAuth.shared.handleURL(url)`

## 남은 것

- 앱 소유: 개인 계정으로 만들어도 된다(동의항목이 닉네임뿐이라 카카오 비즈 앱 불필요). 단 사용자 번호가 앱에 묶여 있어서,
  나중에 법인 명의로 **새 앱**을 만들면 기존 가입자가 다른 계정이 된다 → 실사용자가 생긴 뒤엔 새로 만들지 말고 앱을 법인으로 **옮긴다**
  (카카오는 앱 이전 기능 있음, 네이버는 방법 확인 필요)

- 회원 탈퇴를 만들 때 카카오는 **연결 끊기**(`UserApi.instance.unlink()`), 네이버는 **토큰 삭제**(`logOutAndDeleteToken`)도 함께
- 출시 빌드에서 이메일(테스트 계정) 로그인을 숨길지 결정
