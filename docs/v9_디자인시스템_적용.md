# 기획 시안 v9 → 앱 디자인 시스템 적용

출처: `gyumsa-home-v9` (React/Vite 시안) — `src/design.css`, `src/Explore.jsx`,
`src/HomeCompact.jsx`, `src/V8.jsx`, `src/V9.jsx`, `src/App.jsx`

시안의 색·서체·컴포넌트 규격을 앱 전체의 기준으로 옮기고, 홈과 하단 1차 메뉴를
v9 구조로 맞춘 기록이다.

## 1. 리소스

### 서체 — Pretendard 번들

시안은 `design.css` 첫 줄에서 CDN으로 Pretendard를 불러온다. 앱은 네트워크 없이도
같은 글자 모양이 나와야 하므로 ttf 4종을 `assets/fonts/`에 넣고 `pubspec.yaml`에
등록했다. (Regular 400 / Medium 500 / SemiBold 600 / Bold 700, 합계 약 11MB)

시안의 font-weight는 550·650·720·730·740처럼 100 단위가 아니다.
Flutter가 가진 값으로 내림 맞춤했다 — 720·730·740 → w700, 650 → w600, 550 → w500.

letter-spacing은 CSS의 `em`(글자 크기 비례)이라, Flutter에서는 스타일마다
`fontSize * 비율`을 직접 계산해 넣는다. (`AppType._t`)

### 아이콘 — 이모지 → 선형 아이콘

시안은 stroke 1.8의 얇은 선 아이콘(`motion.jsx`의 `<Icon name="…"/>`)을 쓴다.
같은 그림이 Flutter에 없으므로 결이 가장 가까운 Material outlined/rounded로
1:1 대응표를 만들었다 — `lib/core/widgets/app_icon.dart`.

화면 코드에서는 `Icons.*`를 직접 쓰지 않고 `AppIcon('search')` 같은 **이름**을 쓴다.
나중에 전용 아이콘 폰트로 갈아끼울 때 이 파일 하나만 고치면 된다.

부탁 종류는 `CatEmblem(cat: 'buy')`로 그린다. 데이터(`CATS`)의 이모지는 그대로 두고
화면에서만 선형 아이콘 + 종류별 색 타일로 바꿨다.

## 2. 하단 1차 메뉴

시안 `App.jsx`의 `tabs`와 같게 맞췄다.

| 개편 전 | 개편 후 |
| --- | --- |
| 홈 · 진행 중 · (부탁) · 채팅 · 내정보 | 홈 · **부업** · (부탁하기) · 채팅 · **마이** |

- **부업** = 기존 `BenefitsView`. 예전에는 마이 > '매일의 혜택'으로 들어가는 2차 메뉴였는데,
  시안대로 1차 메뉴로 올렸다. `goPointsHub()`는 이제 화면을 푸시하지 않고 이 탭으로 전환한다.
- **진행 중**은 탭에서 빠졌다. v9도 탭이 아니라 홈 배너로 들어간다. 앱에서는
  홈의 '진행 중 N건' 배너, 채팅 빈 화면의 '지원 내역 확인', 지원 직후 자동 이동 —
  세 경로로 전체화면(`ActivityView`)이 열린다.
- 가운데 '부탁하기'는 노란 사각 버튼(27px, radius 8)이고, 선택된 탭은 아이콘 아래
  3px 점으로 표시한다.

## 3. 홈 = v9 `Explore`

`lib/features/errand/screens/home_content.dart`

| 순서 | 영역 | 시안 |
| --- | --- | --- |
| ① | 지역 헤더 + 검색·지도·알림 | `.explore-header` |
| ② | 진행 중 배너 | `.active-banner` |
| ③ | 누적 수익 + 목표 (짙은 카드) | `.explore .income-compact` |
| ④ | 출석 한 줄 | `.attendance-v8` |
| ⑤ | 주요 서비스 3개 (3열, 세로 정렬) | `.primary-services` |
| ⑥ | 숏컷 5개 + '전체' 펼침 | `.compact-categories` |
| ⑦ | 가볍게 모으기 (미션 2개, 2열) | `.compact-missions` |
| ⑧ | 광고 배너 | v9엔 없으나 수익 지면이라 유지 |
| ⑨ | 지금, 내 주변 — 빠른 칩 · 탭 · 지도/반경/정렬 · 세부 조건 · 종류 칩 | `.nearby-heading` ~ `.category-strip` |
| ⑩ | 목록 또는 지도 | `.task-list` / `.explore-map` |

주요 서비스의 '동네 부탁'·'단기알바'는 시안처럼 화면을 넘기지 않고
⑨ 영역으로 스크롤하며 탭을 바꾼다(`_focusNearby`).
'부탁 전체보기'는 카테고리·조건별 모아보기가 있는 `LocalErrandHubScreen`으로 간다.

### 지도 — 시안의 가짜 핀 → 실제 네이버 지도

시안 `.explore-map`은 CSS 배경 위에 핀을 절대 좌표로 뿌린 **그림**이고,
"실제 지도/경로 안내가 아닙니다"라는 문구가 붙어 있다.

앱은 같은 자리에 실제 네이버 지도(`MapCanvas` → `flutter_naver_map`)를 넣었다.
지도에 올라가는 결과는 **목록과 완전히 같은 조건**이고(반경·정렬·종류·30분),
좌표가 없는 부탁(내가 방금 올린 것 등)은 지도에 찍을 수 없으므로 개수를 따로 알린다.
핀을 누르면 아래에 해당 부탁 한 줄이 뜬다.

지도 시작 위치는 `lib/features/errand/screens/map/map_centers.dart` 한 곳에서 관리한다.
전체 지도 화면과 홈 인라인 지도가 같은 함수를 쓰므로, 목록에서 지도로 바꿨을 때
다른 동네가 보이는 일이 없다.

## 5. 아직 남은 것

- **부탁하기 3단계 폼**(`post_request.dart`)을 시안 `CreateRequest` 구조로 바꾸고,
  장소 단계에 지도 위치 선택을 넣는 작업. 주소 검색까지 하려면 NCP 콘솔에서
  **Geocoding / Search API 키**를 따로 발급해 `core/config/`에 넣어야 한다
  (현재 `naverMapClientId`는 Dynamic Map 전용).
- 부업·마이·상세·목록 등 나머지 화면의 이모지를 `AppIcon`으로 정리하고
  여백을 22px 기준으로 맞추는 일. 색·서체는 토큰 교체로 이미 반영됐다.
- 마이 화면에 '진행 중인 부탁 확인' 진입점 추가 (시안 `Profile`의 `profile-progress`).
