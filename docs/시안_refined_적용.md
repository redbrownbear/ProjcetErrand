# 기획 시안 `gyumsa-refined` → 앱 적용 기록

출처: `gyumsa-refined (4).html` (기획자 최신 시안, v9 빌드 위에 덧입힌 개편본)

v9 이후 시안이 바꾼 것은 크게 넷이다.

1. **색·모서리** — 전체 화면을 따뜻한 톤으로 다시 칠했다.
2. **홈** — 인사말 · 출석 달력 카드 · 겸사겸사 소식이 새로 들어왔다.
3. **부업** — 혜택 나열 화면에서 **미션 중심 화면**으로 바뀌고, 참여 흐름이 생겼다.
4. **등록** — 일상 부탁 / 해외 사다주기 / 단기알바 모집으로 갈래가 나뉘었다.

## 1. 디자인 토큰

시안은 v9의 `design.css` 위에 `:root`를 다시 덮어쓴다. 그 값을 그대로 옮겼다.

| 토큰 | v9 | refined |
| --- | --- | --- |
| `ink` | `#202124` | `#26302E` |
| `sub` | `#7C8087` | `#8B9294` |
| `line` | `#ECEEF1` | `#EEF0EC` |
| `page` | `#F6F7F9` | `#F7F8F5` |
| `yellow` | `#FADD53` | `#FFD95C` |
| `green` | `#286C57` | `#318D74` |
| `navActive` | `#272C34` | `#328B72` |
| `btnPrimary` | `#F7DC67` | `#FFE07A` |
| `btnSecondary` | `#F3F5F8` | `#F0F4ED` |

모서리도 한 단계씩 더 둥글다 — `AppRadius` surface 22→23 · card 16→20 · tile 14→15 ·
emblem 15→18 · chip 11→12.

주요 서비스 3개(`.primary-services`)는 테두리를 빼고 파스텔 면으로만 구분한다.
출석·소식·목표 게이지처럼 새 화면에서만 쓰는 색은 `AppColors`에 이름을 붙여 모았다.

## 2. 홈

순서: 지역 헤더 → 진행 중 배너 → **인사말** → **출석 카드** → **겸사겸사 소식** →
누적 수익 → 주요 서비스 3개 → 숏컷 → 가볍게 모으기 → 광고 → 지금 내 주변 → 더 둘러보기.

### 출석 — 한 줄에서 달력으로

개편 전에는 "오늘 출석하고 +100P" 한 줄이었다. 시안은 이번 달 달력을 항상 펼쳐 두고,
월 누적·연속 두 게이지를 그 아래에 둔다.

보상 규칙도 시안 기준으로 바꿨다 (`AttendRules`).

| | 개편 전 | refined |
| --- | --- | --- |
| 매일 | 100P | **1P** |
| 연속 | 3일 300P · 7일 1,000P · 30일 5,000P | **7일마다 10P** |
| 월 누적 | (없음) | **20일 달성 시 100P** |

한국 시간 자정 기준이고, 하루 쉬면 연속 일수만 끊긴다. 월 누적은 매월 1일 새로 시작한다.

**달력을 그리려면 지나간 날짜가 남아야 한다.** 기존 원장(`RewardLedger`)은
`benefit:attend` 한 키에 마지막 날짜만 덮어썼기 때문에 "오늘 받았는지"밖에 알 수 없었다.
그래서 하루에 한 칸씩 `benefit:attend:2026-09-21` 키로 쌓는다(`Attendance`). 원장은
로그인 시 `users/{uid}/ledger`로도 올라가므로 기기를 바꿔도 달력이 이어진다.
개편 전 키로 오늘 이미 받았다면 오늘 칸도 채워, 같은 날 두 번 받지 못하게 한다.

출석은 **홈 한 곳**에만 둔다. 부업 탭에 있던 `AttendStreak`는 지웠다.

### 겸사겸사 소식

세 장을 점·화살표로 넘겨 보는 카드다(`NewsCard`). 세 번째는 광고 지면이라
'광고' 표시를 달고 브랜드 협업 안내로 간다.

| 소식 | 도착지 |
| --- | --- |
| 해외 사다주기가 더 안심되게 | 소식 상세 → 해외 부탁 |
| 하루의 빈 시간을 새로운 기회로 | 소식 상세 → 단기알바 모집 안내 |
| 좋은 브랜드와 일상이 만나는 곳 (광고) | 브랜드 협업 안내 |

## 3. 부업 탭

`BenefitsView`(혜택 나열)를 1차 화면에서 내리고 `SideJobView`로 바꿨다.

- 제목 '오늘은 뭘 해볼까요?' + 브랜드 협업 바로가기
- 내 포인트 / 공동구매 두 칸
- **가볍게 시작해요** — 3분 이내·구매 없음 미션 2개.
  참여 중인 미션이 있으면 '이어서 참여해요'로 바뀐다.
- 검색 · 상태 탭(전체 / 참여 중 / 적립 완료) · 종류 칩 · 조건 칩(3분 이내 / 구매 없음)
- 미션 목록 — 적립을 끝낸 미션은 아래로 내린다
- 겸사겸사 파트너 배너

### 미션 참여 흐름

상세가 참여 시작 → 인증 제출 → 검수 → 적립 네 단계를 따라간다
(`PartnerMissionDetailScreen`). 중간 단계는 `MissionProgress`(이 기기)에 남고,
적립 완료는 기존 `doneMissions`가 그대로 맡는다.

목록에서 **구매가 필요한 미션인지**를 조건 옆에 같이 보여준다(`MissionMeta.costTag`).
포인트만 보고 들어갔다가 결제가 필요한 미션을 만나지 않게 하려는 것이다.

### 시안과 다르게 둔 것

- 시안에 없는 규제 고지(§19 `Disclosures`)는 미션 상세에 그대로 남겼다. 법적으로 필요하다.
- 시안에 없는 '완료 인정'(`m.verify`) 줄도 남겼다. §3·§4가 요구한 객관적 완료 기준이다.
- 앱에는 시안(20개)보다 많은 25개 미션이 있다. 연구·상담 미션이 묻히지 않게
  종류 칩에 '연구·상담' 한 칸을 더 뒀다.
- 광고 보기·프로필 완성·친구 추천 같은 기존 적립은 시안에 없다. 지우지 않고
  '매일의 혜택' 한 줄 뒤(`BenefitsView`)로 옮겼다.

## 4. 브랜드 협업 (`lib/features/partner`)

브랜드·판매사가 제안서를 쓰는 지면이 새로 생겼다.

- `BrandHubScreen` — 협업 종류 3가지와 진행 절차 3단계
- `PartnerProposalScreen` — 기업 미션 / 공동구매 두 종류가 같은 폼을 쓴다

제안서는 **이 기기에만** 저장된다(`PartnerRepository`). 실제 담당자 접수는 연동 전이며
화면에도 그렇게 밝혀 둔다.

## 5. 등록 갈래와 단기알바 모집

'부탁하기'를 누르면 먼저 갈래를 고른다(`CreateChoiceScreen`).

| 갈래 | 화면 |
| --- | --- |
| 일상 부탁 | `PostRequest(initialKind: 'ask')` |
| 해외 사다주기 | `PostRequest(initialKind: 'sea')` |
| 단기알바 모집 | `JobPostScreen` |

단기알바는 **채용**이라 일상 부탁과 같은 폼으로 받으면 안 된다. 회사와 업무 →
근무 조건 → 급여와 모집 세 단계로 나누고, 단계마다 막는다.

- 1단계: 제목(2자 이상) · 회사 · 회사 주소 · 하는 일(10자 이상)
- 2단계: 근무 장소 · 미래의 시작/종료 · 휴게 제외 근무시간 > 0 · 모집 인원 ≥ 1
- 3단계: 급여 > 0 · 지급일 ≥ 근무 종료일 · 지원 마감(현재 이후, 근무 시작 이전) ·
  담당자 · 확인 체크 · (이메일 지원이면) 이메일 형식

모집글은 `JobPostingRepository`(이 기기)에 저장되고 단기알바 화면 맨 위 '내가 올린 모집'에
나온다. 예시 공고(`DayJob`, 제휴사에서 받아 온 것)와는 별도 모델이다.

## 6. 아직 옮기지 않은 것

시안의 **해외 사다주기 거래 흐름**은 이번에 넣지 않았다. 분량이 가장 크고,
돈이 오가는 단계라 결제·정산 설계를 함께 봐야 한다.

- 가격변동 예비금 · 상품 구매 한도 · 통관 예비비
- 고정환율 정산과 영수증 제출, 차액 카드 부분취소
- 안전결제(이용료 상품가+보상의 1.5%, 최소 500원) / 직접송금 선택
- 구매 전 추가 예산 요청·승인, 수령확정과 지급 보류, 이의제기·문제 신고

지금은 홈 소식의 '해외 사다주기가 더 안심되게'가 기존 해외 부탁 화면으로 간다.
관련 시안 코드는 `G3SeaForm`·`G3SeaCase`·`G3PaymentChoice`에 있다.
